# 实现结构

`src/server` 启动 stdio、注册生命周期。`src/tools` 定义 schema、包装业务错误、处理阅读和结果分页。`src/providers` 统一搜索、解析、缓存、HTTP 与浏览器兜底；`src/browser/worker.ts` 是隔离子进程，只接受固定 search/resolve/article/status 操作，不加载用户适配器，也不接受 JavaScript 输入。通过进程参数数组启动，可取消和超时。

`src/browser/managed.ts` 为默认浏览器实现：Playwright Core 启动项目独占 Chrome profile；解析并固定允许主机的公网地址，拒绝其他 DNS。每页 CDP Fetch 从 Request 阶段检查所有导航、重定向和资源，另有 context 级请求检查及 WebSocket 拒绝。启动时用不可解析测试域名确认请求在解析/连接之前已被阻止。原 OpenCLI Bridge 仅保留诊断。此调整用于完成方案要求的逐请求网络约束，未改变 MCP 工具名称。

`src/resolver` 校验微信公众号普通短链接、含 biz 的长链接，以及搜狗生成的签名文章链接。仅清除已列明的跟踪/会话参数，保留 sn、signature 等文章访问参数。搜狗候选 URL 去掉临时 token，身份以正文中经过格式核验的 biz/mid/idx 为准。

`src/parser` 使用 DOM 选择器和静态字段解析，不执行 HTML 内的脚本。标题、作者、账号与日期分别提取。正文转为版本内稳定的有序块；清洗快照去掉脚本、表单和事件属性。图片下载状态与正文状态分开。缺失字段不猜测，音视频和附件只保存引用。

`src/storage` 使用 Node 内置 SQLite，WAL、参数化查询、schema 版本、文章身份与 URL 约束、独立正文版本、候选 TTL、刷新尝试和逐项检查点。文件先原子提交，再写数据库事务。数据库原文是检索来源。中文检索使用 instr 子串，不依赖默认 FTS tokenizer。任务进度也保存在 jobs JSON 中，便于原子恢复。

`src/jobs` 负责预算、筛选、重试、等待、暂停、取消和恢复。搜索页与候选队列先落盘；通过严格筛选后再写正文/媒体。任务运行时间在进度边界累计，停机、暂停与人工等待不计入。整体串行 worker 限制浏览器并发。单篇调用与任务提交依靠唯一身份约束及原子文件提交保持幂等。

页数预算在整个任务的全部查询之间累计；可恢复的强制刷新失败不会用旧缓存完成任务，而是保留正文进入对应等待状态。未知高版本数据库和冲突文章身份在写文件之前被拒绝，防止降级或错误合并覆盖原档案。

`src/export` 固定版本清单、使用内部 ID 命名，生成 Markdown/JSONL/静态 HTML。导出清单从创建起为 incomplete；取消、缺失媒体和文件失败都不能成为完整产物。已经存在的媒体从受控数据根目录复制，HTML 永不直接拼入源页面 HTML。

启动持有 PID 与随机 token 的单实例锁；正常关闭时停止调度、取消在途请求、标记中断并关闭数据库。重启时不会自动继续任务。源码与构建产物中的浏览器脚本分别可计算 SHA-256，wx_status 返回实际运行文件的指纹。

浏览器子进程通过专用 stdin 控制消息取消，先关闭自己创建的 Chrome 后退出；正常取消未在宽限期退出时才终止 worker。父进程断开 stdin 也会触发清理。服务关闭先中止任务与 HTTP/浏览器调用，再关闭数据库；原生集成测试确认取消后同一 profile 可立即复用。

目前不注册条件账号工具、资源 URI 或 prompts。全部必要操作可通过九个工具完成。与原方案仍有差距的项目由 ACCEPTANCE_REPORT.md 记录，不能由本架构说明推断已经通过完整验收。
